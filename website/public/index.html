使用插件

安装与管理指南 ↗
  1. 打开上方仓库，查看支持的平台、所需版本与依赖。
  2. 从插件发布页下载对应系统和架构的 .gaplugin 包，按仓库说明校验下载。
  3. 在“选项 → 插件 → 安装 / 更新插件包”导入；更新后重启生效。
  4. 在“选项 → 插件”管理全局开关，在“仓库设置 → 插件”设置单仓库开关。

GitHub 插件需要安装 gh 并执行 gh auth login。内置插件可以关闭或卸载，卸载后不会强制重装。

开发插件

模板与开发指南 ↗

从模板的 Use this template 创建仓库，克隆后用最小示例初始化。模板默认包含完整 GitHub 插件，也可以保留它继续开发。

pwsh.exe -NoLogo -NoProfile -File scripts/init.ps1 -Id my-plugin -Name "My plugin" -Example minimal

实现业务与配置式界面，提供字典和图标，完成联调测试，再打包为 .gaplugin 并发布到自己的仓库。

分享插件

编辑 README 并提交 PR ↗

向主仓库的 main 分支提交 PR，只修改 README.md 的 Plugin list 表格，添加插件名称和仓库地址：

| My plugin | https://github.com/you/my-plugin |

无需提交插件代码、二进制或修改官网。PR 合并后由维护者生成并部署名单。插件的功能说明、依赖和发布包继续在自己的仓库维护。

列表只记录插件名称和仓库地址，与 README 同步；收录不代表自动内置或安装。

GOOD TO KNOW.

开始之前，
你可能想知道。

需要先安装 Git 吗？

需要。Git Agent 使用系统中已安装的 Git，请确认终端里可以运行 git --version。远程操作使用你现有的 Git / SSH 凭据配置。

一定要配置 AI 才能用吗？

不需要。日常提交、分支、历史、差异和手动合并均可独立使用。AI 是可选辅助功能，需要自备兼容的模型服务，服务商可能收取调用费用。

AI 会看到我的代码吗？

发起 AI 分析时，文件内容、冲突上下文、相关源码和 Git 历史可能发送给你配置的模型服务商。请先确认数据政策与仓库规范，不要在未获许可时发送私有代码。

macOS 提示无法验证开发者怎么办？

当前安装包使用临时签名，尚未经过 Apple 公证。请先核实下载来源，再按 Apple 官方说明操作，不要关闭系统级安全检查。 查看 Apple 指南 ↗
